# Building the documentation site

`docs/site/` is a static HTML site built with [MkDocs](https://www.mkdocs.org/)
and the [Material](https://squidfunk.github.io/mkdocs-material/) theme, from
Markdown source under `docs/site/pages/`. There is no separate "HTML docs"
system distinct from MkDocs — building the HTML output *is* running MkDocs;
the only real split is between the cheap Markdown→HTML render and the
expensive screenshot regeneration that feeds it, covered by two scripts.

| | Layout |
|---|---|
| Config | `docs/site/mkdocs.yml` (`docs_dir: pages`, `site_dir: _site`) |
| Source | `docs/site/pages/*.md`, `docs/site/pages/views/*.md` |
| Committed screenshots | `docs/site/pages/screenshots/*.png` |
| Build output | `docs/site/_site/` (generated, not committed) |

This is unrelated to the `docs/*.md` files one level up (`dependencies.md`,
`daemon-api.md`, `machine-providers.md`, ...) — those are plain Markdown read
directly from the repo (e.g. on GitHub) and are never fed through MkDocs.
Only `docs/site/pages/` becomes the built site.

## Fast path — rebuild the HTML after any doc-text edit

```bash
bash scripts/docs-build.sh      # or scripts\docs-build.cmd on Windows
```

This does three things, in order:

1. `uv sync --extra docs` (from `cli/`) — installs the `docs` optional
   extra (`mkdocs`, `mkdocs-material`, `playwright`; see
   [`docs/dependencies.md`](dependencies.md)'s build-time dependency table).
   Dev-only — none of this ships.
2. `uv run ralphus-docs-lint` — a screenshot-coverage check
   (`cli/src/ralphus/docsgen/lint.py`) that fails the build if a page
   references a screenshot that doesn't exist under
   `docs/site/pages/screenshots/`.
3. `uv run mkdocs build -f docs/site/mkdocs.yml` — the actual render.

Output lands at `docs/site/_site/index.html` — open it directly in a
browser, no server needed. For live-reload while iterating on page text,
run `cd cli && uv run mkdocs serve -f ../docs/site/mkdocs.yml` instead (not
wrapped in a script, since it's an interactive/watch process rather than a
one-shot build).

This step **never touches Playwright** and never rebuilds `ralphus-librarian`
— it only renders Markdown using whatever PNGs are already committed. Safe
and cheap to re-run on every doc edit.

## Heavy path — regenerate the screenshots themselves

Only needed after a `librarian/assets/board.html` UI change (the screenshots
are taken of the real, compiled board):

```bash
bash scripts/docs-screenshots.sh      # or scripts\docs-screenshots.cmd
```

This does four things, in order:

1. `cargo build --package ralphus-librarian` — the screenshots are of the
   real compiled board, not a mock.
2. `uv sync --extra docs` (from `cli/`).
3. `uv run playwright install chromium` — downloads headless Chromium.
4. `uv run ralphus-docs-shots` — spins up the compiled `ralphus-librarian`
   against a deterministic stub `/api/*` server
   (`cli/src/ralphus/docsgen/stub_server.py` + `fixtures.py`), drives it with
   Playwright (`shots.py`), and overwrites
   `docs/site/pages/screenshots/*.png`.

Review the resulting PNG diffs before committing them, then re-run
`docs-build.sh` to fold the new screenshots into the HTML output.

## The CLI help-map block is separate from both of the above

`docs/cli-reference.md`'s generated help-map section (`<!-- BEGIN GENERATED
HELP-MAP -->` ... `<!-- END -->`) is regenerated by a third, standalone
command — `uv run ralphus-docs-helpmap` (`--check` for CI drift detection) —
which calls the compiled `ralphus show help-map` and splices its output in
place. Neither `docs-build.sh` nor `docs-screenshots.sh` runs this for you;
it edits `docs/cli-reference.md` itself (a plain Markdown file, not anything
under `docs/site/`), so run it directly after a CLI subcommand/flag change,
review the diff, and commit it separately from a `docs/site/` rebuild.
